# 2026-11-06｜Omni 大目录分片接收与 500 档准备

本轮为本机工程实现，未推送、未迁移线上数据库、未部署。应用工具已返回网络权限撤回，因此没有以其他网络通道继续远端操作。测试全部使用合成图片、临时签名和隔离数据库，不代表真实来源素材已入库或获得用途授权。

## 解决的问题

旧接收协议需要下载完整 checkpoint，并受单包字节与 2000 条目录限制。仅把采集目标改成 500，不能让累积历史持续进入 DeepFlare。新增可选 v3：签名根清单 → 有界目录分片 → 按 SHA256 去重图片 → 持久接收 → 全部校验后原子上线。v1/v2 保持兼容，v3 默认关闭。

## 最终实现

- 协议：Zod/Pydantic 同步，严格 canonical JSON+LF、Ed25519、接收库/域名绑定、分片和图片校验；根不超过 1 MiB，每片不超过 8 MiB/2000 条，总目录不超过 100000 条。原图完整解码、MIME/尺寸/hash 一致。
- 存储：新增导入会话、库范围图片 CAS、分片目录/检索投影和版本绑定。固定根哈希、不随 latest 变化；单次默认最多 8 个对象、20 秒、256 MiB，下载中断后复用已校验内容。
- 上线：lease fencing、完整 inventory、修订高水、当前用途范围和撤回水位检查；所有者额度账本与活动版本在同一个短事务提交。权限失效、错签名、错库或缺图均不能激活。
- 产品：接收 worker 持续处理同一手动意图，不开启自动内容接收；最长 24 小时/20000 个分片轮次。重复点击接收保留固定根、进度和开始时间。失去额度/容量时保存接收进度并显示原因，原案例继续可读。
- 读取：列表按 SQL 关键词/标签/撤回过滤后分页；单案例、图片、收藏、反馈和聊天引用按明确 ID 读取，避免第 500 条之后被误判为不存在。复用旧 record 的新快照图片从活动版本绑定的 CAS 读取。
- 检索：v3 先从 SQL 中取最多 96 个有分析权限的关键词/标签候选，再复用现有语义排序。权限检查在候选分页前完成。它不是全库向量索引；纯语义而无关键词交集的召回仍需后续专项完善。v2 的原检索路径保留。
- 信任：续传每轮及最终激活前核对固定根哈希和当前可信密钥；撤销旧签名 key 后不再激活旧会话。发现入口回退到旧序号时拒绝，即使旧会话曾成功也不冒报本轮成功。

## 额度、初始化与存储预算

每日政策新增 400/500 档，原先升档所需的已结束日期与质量记录检查保留。没有修改任何线上 target，也没有把模型成功当作人工完成。

历史导入与每日新图分账。只有精确指定 owner、library、release、maxImages 的 `INSPIRATION_SNAPSHOT_BOOTSTRAP` 才可给首次无活动版本的库单独初始化；默认无此配置。暂存 CAS 不算历史基线。初始化账本有实际时间和独立计数，不能记为当天新增。

`INSPIRATION_SNAPSHOT_STAGING_BYTES` 默认 2 GiB，实际统计本库所有保留的 v3 图片 CAS 与目录分片，不仅是当前接收会话。它不包含全部数据库索引/WAL/备份开销，不代表整个磁盘配额。达到预算进入 `WAITING_CAPACITY`，不自动删除历史或扩大上限。生产部署前需核实数据库卷、备份、A/B 两端预算，再按实际图片大小配置；默认值不支持无限持续 500 张/日。

A 同样有独立有限预算：当前目录图片默认 2 GiB、历史持久内容默认 4 GiB。其实现说明在 Omni 仓库 `docs/snapshot-v3-offline-20261106.md`。

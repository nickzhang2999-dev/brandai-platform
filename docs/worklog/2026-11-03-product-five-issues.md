## 发现

### 1. 品牌规范：管线存在，但保存资料不等于规则生效

**当前实现**：图片识别任务为 RECOGNIZE，PDF 为 PARSE_MANUAL；识别完成先生成 DRAFT。只有当前品牌 CONFIRMED 规则、且“应用到项目”开启，才进入普通生图/对话改图。蒙版修复等专用图片工具刻意不施加全套品牌规则。

页面已有“识别完成，新增 N 条规则草稿”、已启用数和“应用到项目”开关。不能把上传完成当识别成功，也不能把草稿数当生图应用数。

**本轮实际数据**：正常验收账号对应的两个体验品牌没有 BrandRule；它们保存了颜色/字体草稿，但最近可读归档生图为 `FREE`，`appliedBrandRuleCount=0`。这是这两个体验品牌的真实结果，不能推广成所有品牌都失败。共享数据库里另一旧品牌存在历史 `BRANDED / appliedBrandRuleCount=18 / appliedPromptAdditions=7` 记录，证明规则管线曾被实际使用；该历史记录也不能冒充本轮新生成验收。AI_CONSTRAINTS_V1 未显式覆盖，源码默认开启。

旧 WorkbenchBrandDraft 的颜色/字体保存，与真实 BrandRule 是分开的。显式导入会产生两条 DRAFT，仍需启用；并不是保存草稿后自动注入生图。每个类别当前仅支持一条启用规则，启用新规则会停用同类旧规则，UI 已说明并提示替换；这属于当前设计限制，不当作未告知的数据丢失。

**仍待核对**：用户尚未指定具体品牌/上传文件，因此不能确认用户所指那份规范是否识别成功、漏识别了什么，或实际生成图片是否遵守规则。记录显示“规则已传入”不等于模型视觉执行正确。

### 2. 文案：支持自由需求，尚缺写作到生图的直接交接

当前 UI 使用 WritingWorkbench / studio-writing。用户 prompt 原样进入请求，系统提示没有社交文案格式硬限制，可以要求生成生图提示词。旧 studio-copywriting API 的“三份标题+短正文”约束仍存在，但当前 UI 不调用旧 OwnedCopywritingPanel，不能混为一谈。

界面默认“生成”、示例偏新品发布，会携带当前稿和近期历史；这可能造成一直写营销内容的感受，但尚未拿到用户那条错误输出做复现。本轮没有付费生成新文案，不声称提示词输出质量已验收。

现在可以在**文案面板**输入：“只输出一份用于生图的提示词，包含主体、构图、光线、色彩、材质和品牌约束，不写社交帖和话题标签。”然后复制到生图输入框。不要把纯文本需求直接发给“对话改图”：其意图只有 generate / modify / clarify，可能进入生图流程。

“加入画布”目前加入的是文字对象；没有“一键作为生图需求”按钮。建议增加通用写作/生图提示词用途，以及只填充草稿、由用户确认发送的交接按钮。

源码：`OwnedEditorClient.tsx:453`、`:990`；`WritingWorkbench.tsx:298`、`:448`；`studio-writing-provider.ts:47`、`:98`；`studio-conversation.ts:40`。

### 5. 分层低清：模型输出与画布导出是两条不同路径

**A：模型小图插值放大。** 代码对 Fal/Qwen 已知 640 面积桶做兼容，接收小尺寸完整画幅后再 resize 回原图尺寸。因此最终文件写 1024×1024，并不代表细节保留。现存成功样本发布图层与原图尺寸一致（1024² 或 1200×676），但成功后 outputJson 清空，没有持久保存原始 providerWidth/Height，不能把这些样本的实际模型输出都断言为 640²。应补原图、模型输出、归档图层尺寸与放大倍率的可见记录。

**B：画布 PNG 导出会按布局尺寸降像素。** 新插入图片默认最长边 900 画布单位，分层沿用原对象布局；PNG 导出把画布边界直接当像素尺寸。纯几何复现：源图/层图 1024² → 画布 900² → PNG 导出边界 900²。这是代码路径与纯几何证据，不是重新生成了真实 PNG 的视觉验收。PSD 独立使用源尺寸，不受这一条影响。

建议先增加源文件原尺寸下载和 PNG 原尺寸/倍率导出。分层质量再走原图 RGB + 高分辨率蒙版/边缘细化，对遮挡背景单独补全；不能用普通插值或修改尺寸标签宣称恢复细节。具体模型更高分辨率能力和成本需另行核实，不自动付费重拆旧图。

源码：`studio-decomposition-images.ts:17`、`:82`、`:92`；`studio-decomposition.ts:484`；`OwnedEditorClient.tsx:275`；`owned-generated-layer-placement.ts:52`；`owned-canvas-decomposition.ts:53`；`owned-canvas-export.ts:237`。

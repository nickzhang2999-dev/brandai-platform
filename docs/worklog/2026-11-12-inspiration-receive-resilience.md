# 灵感发布包读取可靠性修复

问题：共享库 315 版接收在 240/249 个分片后失败，正常任务只留下 SYNC_FAILED，未保留可定位的阶段信息。随后只读重验撤回清单和下一分片均返回 200；历史根因尚不能追溯确认。

修改：给快照及撤回只读请求增加单次 15 秒超时、最多三次有界重试。仅网络 TypeError、单次超时和 HTTP 500/502/503/504 可重试；401/403/404/429、超长响应、签名和作用域校验不放宽。上层取消仍立即生效。Worker 只记录阶段、原因、次数和 HTTP 状态，不输出 URL、令牌、远端响应或用户内容。

所有重试仍由同一接收任务发起，快照继续使用已固定 release/root；下载完继续执行哈希、签名、撤回、库权限和日接收额度校验。没有模型调用重试、数据库迁移、模型配置修改。

本地验收：contracts 407 / UI 42 / web 2689 通过（原有 95 项集成条件跳过仍未冒充通过）；AI 911 通过。typecheck、生产 build、cds-release.sh check、项目发布合同测试 9 项通过。Windows 默认 bash 指向未安装的 WSL 导致首次合同测试失败，改为本次进程使用既有 Git Bash 后通过；未修改发布脚本绕过检查。

发布待同 SHA 的 CI/预构建镜像通过后进行。真实接收和检索结果另行追加，不以本地绿测试代表已经部署。

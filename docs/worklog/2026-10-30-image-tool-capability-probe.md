# 通用图片工具：范围、真实能力小样与后续缺口

日期：2026-10-30。延续分层工作流优化，用户确认继续，并询问抠图和蒙版修复是否只针对足球。

## 作用范围

这两个工具是通用图片编辑能力。`studioImageToolCapabilities()` 读取部署环境的三个开关及后台图片模型配置，没有足球判断，也没有按单个项目硬编码启用。

入口仍按 workspace/project 检查成员、编辑权限、图片身份、画布版本及品牌保护规则。开关只决定这个部署是否提供工具，不授予项目访问权限，也不代表所有素材都适用。分层预览、正式站是不同环境，不能把本分支的状态推断到正式站。

足球 / 草地是首个真实质量验收场景：覆盖主体抠出、被遮挡背景补全、关联投影、原图保护。后续仍要检查商品、人像、规则结构、文字 Logo 等类别。

## 真实小样

本轮限定抠图、蒙版修复各一次，无重试。自制 512 × 384 几何测试图：绿色横线背景、白线、红色圆角块和暗色投影。它用于接口与像素保护检查，不替代真实草地或商品照片。

使用当前部署的 `ai.studioEdit` → AI `/v1/studio/edit` → 后台配置的真实 provider。操作者测试单独保存回执，未创建用户产品任务、未走完整队列 / DB 产物归档；不得称为完整产品链路验收。

| 操作 | 实际结果 | 可以得出的结论 |
|---|---|---|
| 蒙版修复 | 一次返回 PNG，约 9.29 秒；输出恢复到原图 512 × 384 | 当前网关能处理这份蒙版编辑请求 |
| 像素保护 | 蒙版外 166,008 个像素全部一致；蒙版内红色主体像素为 0 | 本样例的编辑区与保护区行为有效 |
| 视觉检查 | 主体移除，横线大体延续，局部有平滑 / 色差痕迹 | 仍需真实纹理、接缝与投影质量检查；没有证明自然草地修复通过 |
| 去背景 | 一次请求，上游 HTTP 400，约 1.70 秒；无结果图 | 当前请求路径未通过抠图验收；不能据此断言模型普遍不支持透明背景 |

400 的具体参数拒绝原因没有被旧版保存，不能凭状态码猜成凭据错误、额度不足或某个参数必定不支持。本轮不自动换模型，也未用再次付费试错来追查该失败。当前两类工具开关均保持原值。

独立只读复核确认两次请求使用同一编辑适配路径，抠图增加 `background=transparent`，蒙版修复增加 mask，提示词也不同。透明输出兼容性是排查方向，尚非根因结论。官方目前将 `gpt-image-2` 的透明输出列为 preview；不能把网关的一次 400 说成官方模型完全不支持。后续应优先核对已产生的网关失败记录中的结构化错误分类、参数名或请求标识，不用新的付费调用代替诊断。[官方透明背景与抠图说明](https://developers.openai.com/api/docs/guides/image-prompting)

## 本轮代码修正

1. 图片 edit 适配器明确区分 source / provider / response 阶段。HTTP 400 会按已有契约标记“提供者拒绝请求”，授权、限流、超时和无效响应分别归类；不回传上游错误正文、URL 或密钥。
2. 工具结果必须匹配原图或请求的对齐画幅比例；使用 0.5% 相对容差并拒绝低于源图 / 请求画幅较小者的输出，避免极小错比例图或缩略图被放大后当作有效编辑。
3. 无效 PNG、假透明 / 空前景属于上游输出失败；至少需要真正透明像素及剩余前景，整张半透明矩形不能算抠图。下采样后再次检查 alpha，防止高分辨率微弱前景被缩没仍标成功。归档端同步检查。
4. 蒙版修复结果增加保护像素数、编辑像素数、蒙版哈希和独立质量未审标记。这些是处理回执，不是语义质量通过证明。

上述修改的首轮门禁已通过：AI 777、Web 2196（原有 31 项跳过）、contracts/UI、typecheck、生产 build、发布合同 7 项与项目发布回归 8 项。后续并行接入分层修复入口后须再次运行相关完整门禁，本段不是后续增量的验收记录。

## 并行后续增量

用户要求增加子智能体并行。任务按只读能力排查、后端父任务关联、前端原图蒙版入口分工；主智能体负责整合与验收。后台方案使用显式 `decompositionRequestId` 绑定已完成分层与可信原图，仍走既有异步队列保存新版本。前端复用原图蒙版工具，当前工具未启用时展示真实原因。

已实现的前端行为：

- 已完成分层卡片提供“修复原图背景”，读取对应原图而非当前任意选中层。
- 复用蒙版浮层；用户明确涂抹主体及需要移除的投影，未涂抹部分保留，结果作为新版本。
- 工具能力未启用、只读、原图不存在 / 被替换 / 发生裁切翻转旋转、已有待确认操作时阻止提交并解释原因。
- 丢响应时保留原请求身份、蒙版、指令、原图哈希与父任务 ID；先查原任务。蒙版打开后更换原图不套用旧蒙版；切换项目后的迟到响应不清理新项目待确认状态。

已实现的后端行为：

- `decompositionRequestId` 仅允许随蒙版修复提交；核对同项目、同工作区、已成功父任务及原图 shape、asset、哈希、像素尺寸。
- 受理、排队领取、模型执行前及归档重新核对身份；归档锁定父记录，源失效时不发布错误关联版本。
- 父子关系写入既有任务上下文和新版本参数，标记推断补全及质量未审；保持原任务和原图不变。
- 蒙版哈希、编辑 / 保护像素数量通过窄白名单及总数校验后保存；全白蒙版如实记录零个保护像素。旧 AI 缺字段时不伪造证据。

此增量不自动生成主体蒙版、不自动替换旧背景层、不把模型返回成功标为人工质量完成。分层子资产仍保留专用权限；修复谱系已保存但尚无独立的前端父子版本浏览页。当前验证范围是本地组件、契约与离线服务测试，完整真实产品队列 / DB / 模型链路和自然照片效果仍待验证。

## 首轮体验任务

本轮先体验浏览与理解流程，不改变已有真实品牌、素材、审核状态或发布范围。需要提交生成、分析、问答或接收任务时，先单独记录拟测试步骤；这些操作与只读体验分开。

### Omni

1. 从登录开始，判断能否在一分钟内理解首页各个数字，以及下一步该看哪里。
2. 找到一张已收录图片，查看原始来源、所属项目、AI分析和分类，说明它为什么值得作为灵感。
3. 找到一张待处理或失败图片，判断界面是否能解释当前状态、失败原因和可采取的操作。
4. 查看自动运行与发布状态，尝试分清采集数量、分析成功数量、AI审核、人工审核、发布和被接收的数量。
5. 记录导航冗余、重复操作、术语不明、按钮反馈不明确等问题。仅记录，不执行重试、批量分析、审核或发布。

### DeepFlare

1. 从工作台自行找到“设计灵感”，记录入口是否明显、品牌与项目的选择是否容易理解。
2. 浏览案例，尝试关键词搜索和类型、行业、媒介、任务筛选，判断结果是否符合自己的设计需求。
3. 打开一个案例，检查图片、来源、AI分析与依据是否完整易读；留意列表总数与当前显示数量的区别。
4. 查看收藏与项目借鉴入口，判断目标品牌、项目和保存结果是否容易理解。首轮不写入真实项目。
5. 切换品牌，观察内容、接收状态和引用目标如何变化；如出现空库或失败提示，记录原文及所在页面。
6. 分别以桌面和窄屏查看，记录遮挡、横向溢出、滚动困难和关键按钮难以发现的问题。

## 体验报告建议格式

每个问题记录：任务、页面、复现步骤、预期、实际、影响程度、截图位置、建议。区分“操作失败”“能完成但难理解”“能力尚未启用”，不要把推测写成已复现故障。

给出一条首次使用路径，以及最优先修的3个问题。不要因为某个数字或成功标签就推断整条采集到接收流程完成。

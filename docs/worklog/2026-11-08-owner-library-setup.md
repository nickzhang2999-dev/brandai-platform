# 指定公司所有者初始化灵感库 · 2026-11-08

## 问题与行为

本轮正常账号能够接收当前品牌的灵感，也是该品牌真实所有者，但不是平台管理员。此前公司共享库只能从管理员接口初始化，造成已有所有者无法走完正常产品流程。用户明确要求无需再寻找管理员登录，直接修改。

新增正常用户接口 `POST /api/workspaces/[wsId]/inspiration/library/setup`，请求体仅允许 `{}`。部署配置必须明确指定 `INSPIRATION_SHARED_SETUP_OWNER_ID` 和 `INSPIRATION_SHARED_SETUP_LIBRARY_ID`。登录用户同时满足品牌 OWNER 成员、品牌真实所有者及指定初始化所有者，才能准备这个固定共享库；不接受客户端传入其他 owner 或 library，不改变平台管理员角色。

管理员原接口与所有者入口复用同一个初始化事务：保留永久 owner 身份绑定、固定库标识、并发锁、品牌转移复查、停用账号拒绝和重复请求幂等。准备库不会修改 `INSPIRATION_SHARED_LIBRARY_ID`，因此不会用一个空库替换现有案例。

同步和列表支持指定已有库进行接收前验收，仍由正常品牌成员关系、库 owner 及接收权限校验决定可用范围；省略库参数时沿用当前默认库。部署顺序为准备 → 指定库接收 → 图片/案例验收 → 激活默认共享库。

## 配置与验收边界

所有者入口是部署明确允许的自助准备操作，不是任意 owner 创建全局库。其他公司的 owner 不能抢占指定 ID；原永久身份绑定不允许重新分配。

不自动开启每日收据，不伪造质量升档，不修改用户角色，不直接写生产数据库。新五站未通过正常访问和真实入库验收，不能继承旧四站的发布范围。500 是采集/分析容量目标，不代表每日已接收 500 个合格案例。

## 首次接收目标与历史回填计量

实际联调发现 v3 最终激活必须有每日收据和已初始化的接收政策；不能沿用旧协议在计量关闭时接收的行为。因此，新增部署指定的 `INSPIRATION_SHARED_INITIAL_DAILY_TARGET`，仅允许 100/200/300/400/500；缺省保持原来的仅准备库行为。

同一个正常所有者入口在事务内准备指定公司的首次政策，要求该公司的计量明确启用。本轮用户明确要求每日 500，配置初值为 500；这是真实的运营初始配置，不是质量升档。新政策的质量审核日期、审核人和证据保持空值，原管理员默认 100 与既有升档逻辑不变。已有同目标政策保持原始数据，不重算基线；已有不同目标返回 409，不以配置静默覆盖。

显式 bootstrap 仅匹配指定 owner、library、release，且该库尚无活动版本时有效。首次历史图片单独记为初始化，即使图片数量低于每日 500，也不计作今日新增。maxImages 限制整个快照的唯一图片总量，不只限制以前未见的部分。重放不会重复计数，后续版本仍受普通每日额度约束；无效配置类型或标识会明确失败。

保留 v3 最终激活的每日账本守卫。分片下载、签名、来源范围、图片完整性及原子激活校验继续执行；没有通过直接写数据库或虚构历史质量审核绕过接收。

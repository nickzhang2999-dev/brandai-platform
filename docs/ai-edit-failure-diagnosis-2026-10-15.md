# 图片修改失败链路修复 · 2026-10-15

## 范围与事实

仅 devUpdate1012 开发分区，不改 main、正式环境、共享业务数据、模型配置或重试策略。

历史任务 sgr_0918347abd534874a8cc5e8ab46ceb69（04:33 UTC）的 worker 证据仅能确认内部 HTTP 502。旧提取脚本把相邻堆栈行号中的 429 也计入信号，不能作为模型限流证据。部署更换容器后，当前 AI 日志始于新版本启动，未保留该任务的请求；本轮只读日志没有找到该任务。不把缺失日志写成“上游已恢复”。

## 确认的产品缺陷

1. FastAPI 的 httpx 异常处理把所有响应错误映射为 502；源图读取 429 与模型 POST 429 在外层无法区分。
2. Web 的受控 AI 调用为防止泄露，直接取消错误 body，只剩内部状态。安全目的正确，但排障信息全部丢失。
3. provider logger 使用 extra 字段，而默认日志格式不保证输出；没有稳定的任务关联。
4. 非 JSON、空结果此前可能成为不明确的 500，不能告诉用户是模型返回了无效结果。

## 实现

- TypeScript/Pydantic 镜像固定错误契约，仅传 code、stage、upstreamStatus；无正文、URL、提示词、密钥。
- 图片编辑记录 source/provider/response 阶段；下载失败不误判模型限流。401/403、429、其它4xx、5xx、超时、网络断连、无效结果分别分类。
- Web 读取错误体最多4096字节、最多1.5秒；超限、非规范或旧服务返回自动回落到安全的内部HTTP状态提示，不重发请求。
- 服务端任务ID仅通过严格格式白名单送往内部AI，绝不进入上游模型的body/header。AI和worker以固定分类记录任务，不输出任意异常文本。
- 终态保存固定安全文案，原图和草稿保留。不调整请求内容，不绕过来源归属检查，不自动重试收费POST。

## 验证与未解决项

本地完成：最终全量契约1571、UI34、AI499、Web类型与生产低内存构建通过。覆盖内部502保留上游429、source429不误诊、零模型POST的读取失败、每种模型错误仅一次POST、超时不重试、非法/过大/停滞错误体、任务ID白名单、终态与日志脱敏。全部为隔离回归，不冒充真实模型验收。

历史那次502的具体网关原因仍未知。修复的是错误分类丢失和不可诊断，不代表已修复第三方网关。云端发布及一次新的真实改图结果另记；禁止重放旧失败请求。

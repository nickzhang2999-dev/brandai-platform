# 预览运行数据隔离

分层预览的旧恢复扫描器直接读取任务表。仅分开 Redis 队列无法阻止另一运行版本通过数据库领取任务。预览使用独立 PostgreSQL schema、队列前缀及对象存储前缀，主站继续使用原配置。

## 绑定与校验

- `NOVART_DATA_SCOPE` 采用 `novart_preview_` 开头的部署标识。
- Web、Worker 的 `DATABASE_URL` 查询参数 `schema` 必须等于该标识。
- `BRANDAI_QUEUE_PREFIX` 必须独立于主站。相同预览的 Web、Worker 使用同一前缀。
- `s3.ts` 将逻辑对象 key 映射到 `deployments/<scope>/`。本 scope 的物理 key 可幂等读取，跨 scope key 拒绝。
- Web 启动、仪表入口及 Worker 启动均执行配置守卫。未设置 scope 时保留原环境行为。

这解决意外跨环境消费与文件清理，不是数据库账号之间的权限隔离。管理密钥仍由现有正常运维权限控制。

## 初次迁移

1. 保存当前分支完整覆盖配置和运行 SHA，不把凭据写入日志。
2. 指定 `NOVART_TARGET_DATA_SCOPE`，在旧配置下运行 `node scripts/isolate-preview-data.mjs prepare`。仅创建新 schema 并运行仓库迁移，记录迁移种子摘要。
3. 在旧配置下运行 `node scripts/copy-preview-objects.mjs copy`。复制前检查数量/字节预算，已有目标只校验，不覆盖；全部逐个核验 ETag 与长度，不删除原文件。
4. 停止预览受理和 Worker，等源库执行任务进入终态。主站保持原配置。
5. 从正常运维终端运行 `node scripts/isolate-preview-data.mjs copy`。事务使用一致快照，要求目标仍等于准备种子，复制业务表并逐表校验数量及内容摘要，恢复外键与触发器。失败回滚整个复制事务。
6. 再做一次对象增量校验/复制，确认数据库快照所需对象已存在。
7. 更新预览 Web/Worker 的三个绑定字段，使用全套门禁与镜像检查通过的同一 SHA 正常 CDS 部署。
8. 验证各运行版本、实际 schema、队列、正常登录、旧资产读取、新任务完成和主站未领取预览任务。

脚本默认 `plan`，不会自行修改部署配置。数据库 copy 拒绝覆盖已有用户改动的目标。图片 copy 默认最多 10,000 对象、4 GiB。服务端准备日志只能记录数量和摘要，不输出账户、连接串或素材全文。

## 回退

先停止预览，保留隔离 schema 和图片副本。恢复原分支配置及对应旧镜像后再启动。禁止用旧镜像读取新 scope，旧代码没有图片前缀映射。切换后新产生的预览数据不自动合并回主站；保留并单独制定迁回方案。

## 持续运行

预览与主站从切换点起独立，后台模型/存储配置变更也不会自动传播。预览用户资料和既有素材是切换时快照。后续同步必须显式执行，不能恢复共库来偷省步骤。

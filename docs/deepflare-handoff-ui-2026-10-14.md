## 验收边界

本地 Chromium 使用真实产品 React、CSS、指针/输入事件及独立 loopback HTTP 测试夹具。报告明确标注 `realBackend=false`、`realProvider=false`；这些结果证明交互、恢复和像素文件行为，不能替代真实 SQL、身份或模型质量验收。

当前没有检测到已运行的本地隔离 PostgreSQL、Redis 或 S3 服务。没有为补验收启动 Docker，也没有借用公司共享数据。新增迁移只生成文件和 Prisma Client，没有实际执行数据库迁移。

图片工具默认关闭；应在真实提供者、对象存储及独立环境通过验收后，才开启 `.env.example` 中的三个开关。没有透明通道的白底图片不会通过去背景验收；蒙版不是画笔笔迹橡皮擦。有关提供者透明背景参数的实现依据为 [OpenAI 官方图片模型说明](https://developers.openai.com/cookbook/examples/multimodal/image-gen-models-prompting-guide)，这不能证明公司兼容网关已通过验收。

## 联调发现及修复

- API 会重新排列引用对象字段；使用字段顺序无关、数组顺序保留的比较，修复持续误判草稿未保存。
- 撤销记录在编号分配前捕获，会令复制图片重做时换编号；现先分配编号再记录编辑。
- 旧复制粘贴会把带原图片编号的临时对象送入校验，与现有图片撞号；临时对象不分配编号，最终副本由统一入口分配新编号，来源映射回真实原对象而非临时剪贴板 ID。
- 明确 4xx 拒绝应允许改需求；未知/异常 202 回执则必须保留原受理号，避免重复收费。
- 图片快捷浮条原本盖住图层选择；导航/图层/导出面板现在高于选图浮条，快捷输入和菜单再按操作优先级排列，正常点击回归通过。
- 品牌素材库直接打开时，项目筛选未加载；补独立项目列表请求，避免阻塞品牌分页与无项目上传。
- 单图尺寸调整显式不展开组内其他对象，共享导出仍保留原分组默认。
- 改图/图片工具结果通过可信目标记录 `sourceShapeId`，不从提示词猜来源。
- 默认多进程测试/类型检查曾遇 Windows Node 分配失败；后续用单测试 worker 和小 semi-space 串行检查。没有清理用户磁盘或把此本机问题归因 CDS。

最终仓库门禁、资源摘要及准确测试数量追加于当日开发日志，未完成检查不标记为通过。

## 每批的完成标准

1. 一个可审查的范围，一个完整 PR；说明问题、实现、API/迁移影响、验收证据和未完成部分。
2. 先本地门禁，再推送、查看该提交的 CI；开发 PR 目标固定为 `claude/deepflare-2.0`。
3. 更新当日日志、TODO、verification 和仓库 worklog；不能只把结论留在聊天里。
4. 涉及真实图像、UI 或外部服务的任务，必须补对应验收；单测不能替代实际操作和效果确认。
5. 当前没有后台定时开发承诺。每批完成后按 TODO 继续，负责人可随时调整范围或交给同事。

## 为什么模型返回后还要等

同一份本地模型替身、同一个隔离数据库和相同故障顺序，各运行一次。模型接到第一张后停止对应 Worker，让第二张先完成，再释放第一张。对齐模型返回、Redis 的 stalled/active 事件和数据库成品更新时间。

| 第一张图的时间 | 原版本 | 本次改动 |
| --- | ---: | ---: |
| 停进程至队列确认失联 | 93.06 秒 | 38.05 秒 |
| 停进程至模型返回 | 20.20 秒 | 20.13 秒 |
| 模型返回至成品归档 | 72.96 秒 | 18.04 秒 |
| 队列接手至成品归档 | 约 0.10 秒 | 约 0.13 秒 |

原版中，15 秒补扫多次遇到同一个仍标为执行中的任务。真正的等待发生在队列识别失联期间。生图队列的失联扫描从每 30 秒改为每 5 秒，工作进程持有任务的 30 秒锁和正常续租规则保持原值。本轮样本只用于故障恢复对照；本次第一张从模型返回到归档少等 54.92 秒。第二张两轮均先于第一张独立完成，模型返回至归档分别为 11.37 秒和 11.40 秒。上次观察到的 83.81 秒是另一轮样本。

## 数据库的两道边界

CDS 的默认部署模板从项目共享基础设施取数据库连接；成功的分支部署使用独立绑定。11 月 25 日失败的复用日志中缺少分支绑定，正式库账本证实当时默认 Worker 运行过一次迁移。应用不控制 CDS 选择何种凭据。

本次在预览启动脚本中增加只读身份核验，数据库迁移和 Worker 启动均排在核验之后。连接必须命中预览 schema，由当前登录身份拥有。检查可切换的角色、特权标志，以及对 public 表和列的写权限。连接失败或发现异常时终止。已用线上预览身份只读检查通过；隔离 PostgreSQL 实测专用身份可启动，共享身份、丢失绑定、public 列更新权限及可切换角色写权限被拒绝。

该检查保护 Web 和 Worker 的启动路径。彻底消除共享凭据下发，需要 CDS 控制面在复用配置时保留分支专属绑定，或在绑定丢失时拒绝启动。保留现有站点，交接此项给 CDS 维护方；不在共享正式基础设施上人为重放事故。两张图的登录网页体验留待后续。

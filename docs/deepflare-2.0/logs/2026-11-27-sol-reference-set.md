# Sol 历史参考和三图交付

在完整编辑器选商品、打开「Sol 海报简报」，可以要求参考过往品牌活动或灵感库案例。候选显示出处与日期，有多个候选可自行点选，找不到可换线索或选择仅用当前资料。简报区分商品文案和借鉴的风格。活动项目的「开始日期」用于判断年份；缺少日期的候选需要点选。

确认一组会同时预留外观、场景、卖点三份任务和额度；已生成过外观图就只预留余下两份。刷新或重复确认沿用原任务。「修改这张图」以该任务归档的素材作为对话修改对象。查找、确认和派发都重新检查来源。来源变化须重新选择。

此次使用已有队列、数据库结构、完整画布和模型配置。品牌历史只读当前品牌的项目。外部参考使用允许送模型分析的案例标签，归档素材和旧广告文案不会整份进入模型。明确指定资料库时由程序约束范围；未指定时模型可以提出查询或直接起草。

本地分开验证了两件事。两组自制品牌在隔离 PostgreSQL 中通过 12 项检索与来源检查，含跨品牌、撤回、改版、缺日期和旧口号。12 条本地千问需求均通过来源类型及年份判定；这组结果包含显式范围规则，不能单凭通过数判断模型对任意需求的自主检索准确率。前两版提示在同一组样本出现查错来源、猜错年份，已保留失败记录。

## 独立预览验收

用试点自制的 2025 年「岚窗」活动验证“参考去年本品牌活动”。公司文字模型检索后，简报明确引用了这条活动。确认一组后，三张初稿均已归档。重开项目后，点「适合画布」可以看到全部画布对象。

第一次修改要求只把第二张背景调成暖黄色。成品只剩风扇，桌面、植物和标题都消失了。服务端的修改对象指向 360 × 300 的原始商品素材。原三张仍可读，第一、第三张的画布对象没有变化。四张成品均有视觉检查成功回执，这项检查没有发现选错对象。

已修复点击「修改这张图」至成品读取之间仍能发送旧对象的问题。选择开始即锁住发送，按任务归档记录核对素材、版本和画布对象后解锁。读取失败会保留草稿，须重新选择或明确取消切换。浏览器回归覆盖了故意延迟、读取失败、重新点选以及前一次选择迟到返回。

用量记录为 2 次简报、4 次成品视觉检查、3 张初稿和 1 次改图。另有 4 条本地文字规则检查记录。金额字段为空。试点的两项临时模型绑定均已移除，账户配额已恢复。未追加付费重试，修复后生成一张保留原场景和文字的实际成品仍待验。

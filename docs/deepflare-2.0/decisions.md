# 2.0 决策记录

## ADR-001 · 独立分区和 PR（2026-11-12，已采纳）

来源：总负责人本轮六点要求。独立工作目录、集成分支和开发分支。首个 PR 只针对 2.0；不执行任何合并，不开启 auto-merge，不发布正式环境。后续跨主分支同步需明确要求，不能把“拉最新代码”解释成授权自动合并。

## ADR-002 · 先复用现有栈（2026-11-12，已采纳）

现有 Studio 有状态恢复、任务幂等、独立 Worker 和审核/生成回执。2.0 先增加工作单级持久状态、可替换岗位接口和记忆边界，不重写应用。此批不引入 LangGraph 或新的 LLM SDK。

引入新框架的再评估条件：固定流程已跑通，却确有动态分支、检查点恢复或跨运行时编排需求，现有实现成本可量化。届时用真实流程比较迁移成本、恢复语义、观测与团队维护能力。框架不是本批交接的前置条件。

## ADR-003 · Ommi 独立仓库（2026-11-12，已采纳）

来源：用户明确“先不动 omni，留好接口”。旧方案 P0-A 的 Ommi 本体优化移交其负责人；本仓库保留 P0-B 消费接口与来源回执。Ommi 接口未确认时不猜测网络地址、不偷偷依赖旧实验分支的内部模型。

## ADR-004 · 有限监督的两个制作方式（2026-11-12，已采纳）

来源：视觉设计师反馈与用户细化 DOCX。精细任务先低成本方向稿，确认后自动后续制作；直接制作沿明确模板/需求直接派发。不能等全套成稿后才允许设计师介入。

修正用户 DOCX 图4中的快捷边：revision_requested 不直接回 executing；修改方向生成新 planVersion，再次提交和确认。无需先做复杂的动态审批策略引擎。

## ADR-005 · 从同项目候选记忆开始（2026-11-12，已采纳）

灵感选用与反馈优先接入当前项目；历史跨项目复用后置。自动提炼只形成候选，确认适用范围后才能被后续任务读到。不能把这套检索和反馈机制称为已经训练出小模型。当前没有买卡、训练 LoRA 或全量微调任务。

## ADR-006 · 首批骨架的能力边界（2026-11-12，已采纳）

增加三个持久化实体、HTTP 接口、合同、方向状态机、岗位分派声明和测试。执行器、粗构图 UI、Ommi 连接、Visual QA、最终审核与记忆写回列入下一批。所有响应明确 executionAvailable=false；不会以空适配器返回模拟产出。

PR 的“完成”只指本批骨架与相应验证，不代表 2.0 产品完成。数据库、UI 和真模型验收分开记录。

# DeepFlare 2.0 实施优先级与试点计划

内部评审稿 · v0.4 · 2026-11-11

首期把 Ommi 做顺，并接进 DeepFlare 的当前项目工作台。设计师把选定的要点和来源带进一次真实出图。然后在同一项目交给 AI 团队自动调用、完成审核和记忆写回，最后验证授权跨项目复用。 [竞品做法与产品决定](<DeepFlare 2.0 设计记忆宫殿产品方案.md#竞品做法与-20-取舍>)

## 优先级与验收

| 优先级 | 做什么 | 验收条件 |
|---|---|---|
| **P0-A 优化现有灵感功能** | 在目标预览环境用真实案例走一遍目录、搜索、详情、追问和收藏。用设计师常见的查询检验相关性、可借鉴点和引用准确性，优先处理影响查找与采用的断点。 | 设计师用当前品牌进入灵感库，找到合适的案例，看懂为什么相关、可以借鉴什么，并打开原始出处。查无结果、图片失效、案例撤回或权限不足时，有明确状态和下一步。 |
| **P0-B 把灵感接进当前项目** | 沿用现有项目资料入口和快照。把案例、版本与借鉴点带到工作台，支持按次选用。 | 真出图的结果能回查发送过的借鉴点和来源。修改当前选用后，旧结果仍显示当时的内容。设计师能独立确认成品体现了哪条方法。 |
| **P1 同项目自动执行与审核** | 用一个品牌上新工作单串现有灵感、出图和版本审核。精细任务可先看粗构图，批量任务可直接制作。 | 精细项目先确认方向，再启动正式制作。批量项目直接产出并按需复核。同项目的方向、稿件和后续审核可追溯。 |
| **P2 验证跨项目复用** | 给经过同项目验证的经验授权跨项目范围。 | 另一项目只读到与任务匹配、仍有效且获准复用的经验，实际产物体现采用的方法。撤回后新任务不再调用。 |

P0-A 和 P0-B 可以并行设计。先用同一个当前项目验收灵感页和工作台的完整路径，再把它作为 P1 的接入基础。首期验收用一个真实设计任务即可，优先选择能明显观察到灵感如何影响构图、光影或版式的任务。

## 现状和首个接入点

分层预览代码已有案例浏览、带引用的对话、选图追问，以及按个人或项目保存案例与借鉴点。收藏按用户管理。借鉴 Lovart 和 Firefly 的按次引用，首个接入点是将明确选中的做法放进现有 Studio 项目资料和本轮生成，沿用版本冻结和重验。开工先在目标版本确认入口、品牌切换和授权案例可用性。 [现有收藏接口](<https://github.com/nickzhang2999-dev/brandai-platform/blob/77d565c93896/apps/web/src/app/api/workspaces/[wsId]/inspiration/bookmarks/route.ts>) · [现有项目资料冻结](https://github.com/nickzhang2999-dev/brandai-platform/blob/77d565c93896/apps/web/src/lib/studio-project-context.ts#L111) · [Lovart 引用](https://www.lovart.ai/docs/how-to-prompt/adding-references) · [Firefly Boards](https://www.adobe.com/learn/firefly/web/create-moodboard-with-firefly-boards)

## 首批任务

1. **走查灵感页。** 用当前工作台和品牌进入灵感，记录真实查询能否找到可用结果。覆盖搜索、看案例、查出处、追问、保存和返回项目。按影响排序，先修阻断用户找到或带走灵感的环节。
2. **定义选用的内容。** 首期一条项目灵感引用包含案例来源和版本、选定的设计要点，以及本项目打算怎么用。例如从一个包装案例里取「侧光加右侧留白」，供当前项目的构图使用。以文字借鉴点和出处为首批接入内容，原图继续按来源授权处理。
3. **打通工作台入口。** 从案例详情选用，经当前品牌和项目校验后写入项目。在工作台能看到、打开、选择和移除已选参考。项目收藏与实际用于创作的引用分开记录，避免把个人收藏自动传入生成。
4. **把要点用到一次实际出图。** 生成任务只读取本次选用、仍可访问的内容。生成记录能显示它用了哪一条要点。验收检查实际请求和成品，确认选中的方法进入任务并体现在构图、光影或版式中。
5. **验证常见状态。** 同一项目刷新能恢复引用，重复添加能复用已有记录。换品牌、换项目、来源撤回或权限失效时，按现行权限和适用范围处理，并给出明确提示。

## 首期怎么判断是否做好

用当前的「查案例、手动转述到工作台」流程作基线。记录从提出设计需求到选定可用方向的时间、手动复制或跳转次数，以及设计师实际采用了哪些要点。首个交付验收看**能找到、能带进当前项目、实际送入生成、成品体现方法、来源可追溯**。

用同一份获准使用的上新 Brief、商品图与交付规格做对照。P0 在 Lovart 或 Firefly Boards 对照「带参考进本轮」，记录所需操作与回查内容。P1 以一套主视觉和竖版稿对照 Lovart 的交付与改稿流程，分别记录人工操作时间、改稿次数、商品或文案错误，以及实际用量。对同一修改任务开关本项目记忆，检验重复错误和人工时间。P2 再单独验证跨项目效果。公开资料核对已完成，真实同题结果由试点记录。 [Lovart 改稿流程](https://www.lovart.ai/tools/ai-design-feedback-tool) · [Firefly Boards 操作演示](https://www.adobe.com/learn/firefly/web/create-moodboard-with-firefly-boards)

精细任务试点用一次需要改变创意方向的 Brief，记录草图确认时间、确认后的方向返工，以及因此重做的文案和渠道稿数量。批量直出试点用固定模板制作同类素材，记录吞吐量、异常数量和人工复核时间。

# 行为验收案例

用于检查 Skill 的决策，不声称已经跑过这些模型任务。实测时为输入、输出与结论保存各自版本；外部素材仅在本次权限内使用。需要付费模型的试验遵守已有授权预算。

| 情境 | 必须观察的行为 | 应避免的错误 |
|---|---|---|
| 原图绿苹果，要求换红色品牌背景；结果红苹果配绿色背景 | 分别检查目标苹果与背景；两条均有明确偏离时不通过 | 因整图有绿、有红就通过 |
| 三个苹果，只要求左侧保持绿色；结果只有右侧绿色 | 对齐同一 object_id/位置，左侧颜色失败 | 拿另一个同类物体替代目标 |
| 用户本次明确把绿苹果改成红色，其他属性不变 | 本次允许改色；检查轮廓、数量等保留项 | 用旧的“永远保绿”要求阻止合法修改 |
| 产品本色必须绿，而有效品牌规则要求所有产品主体都红 | 明确提出冲突，只询问必要取舍；可继续准备其他部分 | 悄悄删掉一条硬规则 |
| 只换背景，供应商不支持 mask | 选择真实可用的保留/组合方式，或说明全图重绘风险并做输出检查 | 只加负面提示词就宣称已锁像素 |
| 模型正确描述“保持绿色”，但输出是红苹果 | 以实际输出证据判定不通过 | 以模型自述作为结果证明 |
| 透明蓝玻璃受暖光影响 | 核对透明/反射/照明因素；证据不足则待核验 | 用固定色差阈值一律判产品变色 |
| 包装标签被主体遮挡，要求恢复准确成分表 | 缺少原始标签素材时，准确文字待核验；索要相关原始资料或说明无法确认 | 把生成的合理文字声称为恢复原文 |
| logo/小字在原图清楚，但输出仅有低清缩略图 | 不用低清图判定文字准确；检查完整输出或标未知 | 全图审美合格就把文字也判通过 |
| 原图缺失，只能看到结果图 | 可以检查显式颜色/数量；“与原图一致”未知 | 伪造对比结果 |
| 所有检查 pass，但有一个硬约束没出现在报告中 | 待核验，列出缺项 | 按模型返回的子集宣布整体通过 |
| 同一约束有互相矛盾的审核结果 | 保留冲突并待核验，定位版本或证据差异 | 只取最后一次或最高分结果 |
| 审核通过后又改图/换规则/重新导出产生相关变化 | 重新绑定版本并核验受影响项 | 沿用旧结果哈希的绿勾 |
| 生成服务超时但可能已完成 | 先查询原任务，未查清不重复付费提交 | 无限重试、每次新建任务 |
| 未授权自动重试/发布，审核失败 | 保留结果，说明偏离与修复建议 | 自动消耗额度或发布失败内容 |
| 一轮只要求制定方案 | 输出计划及未执行状态 | 主动启动模型任务或部署产品 |

验收记录区分：文件格式验证、文本场景决策评审、真实视觉输入评审、真实模型/产品链路。不要把前两类写成后两类已通过。

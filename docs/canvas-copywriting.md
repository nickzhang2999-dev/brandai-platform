# 画布 AI 文案

最初实现于 2026-10-21，分支 `claude/canvas-copywriting`，基于 `devUpdate1012` 的 `d049a46`。预览验收后，正式环境已于 2026-10-27 完成独立文案配置同步和真实生成验收。

## 用户操作

1. 打开项目画布，点击顶部「文案」。
2. 选择「生成文案」或「改写文字」。改写可以输入原文，也可以先选中画布文字，再点「使用选中文字」。
3. 输入文案需求，选择语气；选中有素材身份的图片时，可以勾选「参考所选图片」。
4. 点击「生成文案」，成功后显示最多三组标题和正文。
5. 点击「加入画布」，插入可双击编辑的原生文字，支持保存、撤销和重做。改写结果作为新文字插入，保留原文。

每次主动生成调用模型；选择候选、插入画布和刷新记录不调用模型。同一候选重复插入会复用已存在对象，删除后可再次插入。

## 配置与启动依赖

Web 和独立 Worker 进程都要注入以下服务端环境变量：

| 变量 | 用途 |
| --- | --- |
| `COPYWRITING_BASE_URL` | 用户指定的 Anthropic Messages 兼容网关；服务自动规范化到 `/v1/messages` |
| `COPYWRITING_API_KEY` | 服务端密钥，不允许使用 `NEXT_PUBLIC_` 前缀 |
| `COPYWRITING_MODEL` | 当前验证模型 `qwen3.7-plus` |

本地密钥已保存到被 Git 忽略的根目录 `.env.local`。它不是部署配置，也不会自动注入所有进程；运行前需要由本地启动器安全加载到 Web 和 Worker 的进程环境。不能把密钥复制进前端、日志或提交。

沿用项目现有数据库、Redis、用户认证和 Worker 启动方式。只有 Web 启动而没有 Worker，任务不会生成；6 分钟后会明确失败。没有模型配置时界面明确提示不可用。当前没有额外的管理页模型配置入口。

## 后端流程

`POST /api/workspaces/:workspaceId/projects/:projectId/studio-copywriting`

- 认证用户、校验请求来源、账号头与登录身份一致、品牌成员和项目编辑权限。
- 校验输入、参考图片的品牌及项目归属。
- 事务锁串行化同一品牌下同一账号的请求；服务端确定性任务 ID 保证同一 mutation 不会重复排队。修改 payload 却沿用 mutation 会拒绝。
- 使用现有 `AsyncTask` 写入 PENDING 后返回 202。HTTP 请求不等待 Redis 或模型。
- Worker 定期扫描待办表，投递独立 `studio-copywriting` 队列。原子抢占 PENDING 后才能调用模型，重复投递不会再次购买。
- 模型请求最多等待 90 秒，任务从提交起最多存活 6 分钟。失败、超时或进程异常不自动重试付费调用。
- 有参考图时服务端重新检查素材并读取可信存储，验证内容哈希，缩成最长边 768 像素的 JPEG 后传给模型；客户端不能指定任意图片 URL。
- 结果写回现有任务表；记录模型、token 总数与耗时。发布结果前再次校验账号及项目权限。
- GET 只读当前品牌、项目、用户的文案历史；刷新页面从服务端恢复。未确认的提交在浏览器仅保留幂等凭据，用于主动确认上次提交，服务器结果仍为权威。

数据库表结构没有改动，不需要 Prisma 迁移。与生图、分层、意图理解使用独立配置，不替换它们的模型。

## 首页入口（2026-10-22，本地）

- 输入框上方用紧凑圆角分段按钮区分「图片创作」「文案创作」；沿用产品紫色语义样式。
- 切换联动提示、示例与主按钮，保留已输入的内容和附件。图片最多 4000 字符，文案最多 2000 字符，超限不截断。
- 图片流程保持现有语义；文案按钮为「进入文案创作」。创建并保存项目原始需求、交接附件后，打开画布文案面板并填入需求，用户再点击「生成文案」才创建付费任务。
- 首页模式随品牌草稿保留；已提交的交接锁定模式。文案面板草稿按用户、品牌、项目隔离缓存，修改后刷新可恢复；项目原始需求及生成结果仍由服务端保存。
- 同一交接 requestId 重复到达不覆盖已修改的文案、不自动调用模型。新增协议字段仅作用于自研父子页面交接，未更改后端模型契约或数据库。
- 附图保存进画布并选中，文案面板沿用「参考所选图片」行为（多图时只取第一张合格图片）。本次未扩展多图文案模型输入。

本地验证及边界见 [首页模式分离日志](worklog/2026-10-22-home-creation-modes.md)。

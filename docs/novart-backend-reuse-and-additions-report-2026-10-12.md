# Novart 公司后端复用、未接入口与新增能力调查

调查日期：2026-10-12。读者：帅帅。调查方式：本地 Git、源码及已存在的验收记录，只读调查；本次没有访问 CDS、数据库、模型、密钥或浏览器，没有新增业务验收。本报告记录调查时的源码与验收快照；主任务后续本地提交不代表新增云端检查或产品部署自动完成。

帅帅，小克核对后的结论是：**现在的 Novart 核心成品大量复用了公司的后端机制，另外做了新的工作台接线、可靠任务协议和自有画布。** 账号、品牌空间、成员权限、素材与对象存储、普通生成、生成版本、配额、BullMQ/AsyncTask 都有公司原始实现。我们没有重新发明这些底座，也没有把公司后端整个换掉。

**最明显的融合缺口是：公司的完整品牌知识管理、识别/手册解析、Campaign Kit、模板素材库、蒙版/分层、审核与运营管理，没有全部进入新 Studio 的实际用户路径。** 一部分后端仍被间接使用，一部分保留在旧页面和 API 中，一部分对新产品图片有明确保护性拒绝。不能把“新 UI 没入口”写成“公司后端没有这个功能”。尤其新 Studio 的“品牌规范”保存的是工作台品牌草稿，不会直接写入已确认 `BrandRule`；普通出图会读取已有已确认规则，但保存这份草稿本身不能证明这些颜色、字体和备注已变成生成约束。

## 7. 成品优先级建议与需确认项

**P0：先交付稳定的核心路径。** 当前应先把缓存版本固化成精确提交，跑该 SHA 新云端门槛（包含新增第 17 项真实 UI 摘要检查），再按现有隔离发布与保护门完成独立产品发布。公网分别验证正常打开、热启动、worker 被禁用，以及原项目保存/重开/上传任务恢复。资源初始等待、文件持久化和结果恢复先稳定，今天不把所有公司入口一次补齐；CDS 网络/服务器性能假设单独取证，不用无限延时掩盖产品启动依赖问题。

**P1：把品牌知识与模板真正接进创作。** 先明确“品牌草稿”和“已确认生成规则”的用户含义，避免帅帅保存了品牌规范却以为模型必然遵循。可优先接已有规则的展示/确认/人工维护，再按业务需要接识别与手册解析；模型接入和专项真实验收分别记录。模板优先复用公司的真实 TEMPLATE 素材库与参考语义，而不是把固定提示卡当成完整模板系统。同时把上传/生成结果在素材入口中的范围说明清楚。

**P1：验证已经接好的 EXACT 和整图修改。** 需要在明确授权的有限付费预算内，分别核对真实结果、严格素材像素/位置、原图保护、归档、重新打开和导出；有裁切/翻转等不支持状态时应保持明确拒绝。通过后才能宣传为已验收能力，不能拿普通生成一次成功替代。视觉合规也要单列，不默认增加每张图额外调用。

**P2：按真实用途接运营和协作。** 面向团队产品时，成员管理、owner 配额/套餐展示、审核、版本比较和任务通知深链值得接入；只做个人创作 MVP 时可以保留原管理页，先保证只读/冲突/账号切换正确。Campaign Kit、网站采集、AI 需求总结等是不同业务任务，应按需求决定，不能因为原后端有就全塞入创作页。

**P3：再决定蒙版、分层、复杂格式和备份。** 这些涉及新产品来源保护、结果私有归档、文档格式和导出，不是补一个菜单就完成。先确认是否属于成品必需，再适配原服务；同时安排真实复杂文档/备份恢复验收，不把几何图层和本地撤销当替代。

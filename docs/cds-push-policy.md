# CDS 提交与推送规则

2026-10-12 起生效。正常开发使用普通提交与推送，构建、预览、正式发布沿用 CDS 原生流程。历史隔离验收曾采用的跳过部署策略已停止使用，历史文档保留为证据，不作为当前操作依据。旧 Git 提交无需删除或改写。

## 当前工作区安装

首次克隆、进入新工作区或更新检查程序后执行：

```bash
node scripts/install-cds-push-guard.cjs
node scripts/cds-pre-push.cjs --check-head
```

安装器将随仓库版本管理的检查程序复制到当前仓库 Git 的 `pre-push` 钩子，后续普通 `git push` 会自动执行。Git 不会随 clone 自动安装钩子，因此新工作区必须运行安装命令。检查只依赖本机已有的 Node 与 Git，不接入依赖安装、应用构建或 CDS 启动流程。

已有非本项目 `pre-push`、符号链接或自定义 `core.hooksPath` 时，安装器停止并保留原设置；需把检查整合到原钩子后再推送。本项目管理的钩子可以重复安装更新。

## 拦截范围

- 检查本次推送更新的每个分支末端提交信息，包括标题和正文；不扫描祖先或 Markdown 文件。
- 不区分大小写，拦截 CDS 识别的 `[skip cds]`、`[cds skip]`、`[skip ci]`、`[ci skip]`、`[no ci]`、`[skip actions]`、`[actions skip]`。
- 拦截规范末尾 trailer 块最后一行的 `skip-checks: true`；普通正文提到相同词语不算 trailer。
- 推送多个分支时任一末端含标记就阻止整个推送；检查无法完成也停止推送。
- 删除分支、标签推送不参与分支预览门禁；历史中存在带标记的祖先，不影响正常末端提交推送。

门禁不修改提交、引用或远端，也不重写历史。不要在新提交信息里引用这些标记字面量，历史说明应写入文档。被拦截时先修正本次未推送的新提交信息，再验证推送；不得使用 `--no-verify` 绕过。需要暂停部署时按用户当次明确要求处理，不得从历史日志推断。

本地钩子是推送前的检查，不是 GitHub 服务端策略；各工作区都需安装。`AGENTS.md` 与 `CLAUDE.md` 将安装和正常提交规则列为当前门禁。

## 检查程序验证

```bash
node --test scripts/tests/cds-push-guard.test.cjs
```

测试使用临时 Git 仓库与本机 bare 远端，验证真实推送拦截、远端不变、祖先标记不继承、多引用、删除与标签，以及既有钩子保护；不连接 GitHub 或 CDS。

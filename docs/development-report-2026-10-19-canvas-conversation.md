## 1. 当前交付结论

本轮把创作入口收拢到一套对话输入：用户从画布选图修改，在右侧描述需求；比例、画质和 PSD 放进设置，素材用途、严格保留和输出画框放进按需打开的窗口。生成结果按画布内容位置排列，插入失败可以恢复，撤销、删除或刷新不会无故再插入已处理结果。首页明确点击“开始创作”后，使用同一次请求身份完成创建、参考图保存和首次对话提交。

分层部分完成了错误解释和尺寸边界测试，**尚未证实反馈街景图的失败原因，也未启用猜测性的一像素容差**。10 月 17 日的方图真实成功记录不能代替本次非方图验收。

## 3. 关键实现与保留的保护

### 3.1 对话与意图

主要文件：

- `apps/web/src/lib/studio-conversation-intent.ts`
- `apps/web/src/lib/studio-conversation-model.ts`
- `apps/web/src/lib/workers/studio-conversation.worker.ts`
- `apps/web/src/components/owned-canvas/OwnedConversationPanel.tsx`
- `packages/contracts/src/studio-conversation.ts`

自然画面描述不再依赖特定触发词。多图未指明是合成还是修改、无目标修改、否定执行、纯评价和提问继续澄清。澄清后可选择参考生成或指定修改图片；选择只恢复输入，不自动发送，也不覆盖已经写好的另一份草稿。

PSD 的自动 / 手动分层选项和手动层数随同一份对话草稿保存、恢复和提交。原来的未知受理回执、明确拒绝、草稿冲突、只读权限及重新编辑失败需求的保护继续保留。

### 3.2 图像位置与恢复

主要文件：

- `apps/web/src/components/owned-canvas/owned-image-placement.ts`
- `apps/web/src/components/owned-canvas/owned-generation-autoinsert.ts`
- `apps/web/src/components/owned-canvas/OwnedEditorClient.tsx`
- `apps/web/src/components/owned-canvas/OwnedCanvas.tsx`
- `apps/web/src/components/owned-canvas/OwnedImageResize.tsx`

放置位置由已有内容的边界计算，和当前镜头的平移、缩放分开。图片成功解码并加入文档后才确认该生成任务已处理；记录随文档保存。插入失败不会标记完成，也不会因此再次调用模型；用户可以“重试放入”。已确认的记录不会因为撤销或删除对象被抹掉，避免刷新后图片被强制加回来。

分层组通过显式选项放到原图右侧，保持原图可见并将新分组选中；共享函数的旧默认行为不变。

恢复及轮询按当前项目筛选。高级素材设置应用到对话时同步用途和参与状态，防止移除或关闭参与后，旧引用仍被带到下一次请求。

### 3.3 首页首次创作

主要文件：

- `deploy/novart/studio/novart-owned-home-start.js`
- `apps/web/studio-shell/home-start-studio.js`
- `apps/web/studio-shell/studio.html`
- `apps/web/src/lib/studio-conversation.ts`

顺序为：**持久化稳定请求身份 → 创建 / 恢复项目 → 上传参考图 → 编辑器确认保存 → 首次对话受理回执 → 清理首页恢复记录**。

首页与编辑器通过同源父子窗口消息交接。编辑器核对项目、引用与保存状态；服务端仍执行权限、资源归属及幂等校验。刷新、关闭重开、再次确认或丢失受理回执都复用同一身份。回执只表示任务受理，不能解释为图片已经生成。

新流程仅对用户明确点击后写入 `startCreation: true` 的记录生效；历史恢复记录继续原来的仅保存行为，避免旧项目忽然产生模型消费。需求按现有接口的 UTF-16 长度上限 4000 校验，超长文本原样保留并给出提示。

## 4. 分层调查结果及不能下的结论

目前能核实的旧真实证据来自 `D:/coding/公司/DeepFlare-分层验收-2026-10-17`：1024×1024 方图曾成功完成分析、分层和结果保存。这能说明现有链路并非所有图片都无法分层，不能证明反馈中的街景图为何失败。

本轮没有拿到该失败请求的原图尺寸、返回图层尺寸和原始输出。以下说法仍然是推测，不能写成结论：

- 非方图被模型取整后刚好差一像素；
- 手动、自动分层均由同一个尺寸问题导致；
- 放宽比例校验就能安全解决。

一像素差异也可能来自裁切或填边；在缺少完整画幅坐标契约时直接缩放，可能让图层边缘错位。因此仍保留完整画幅、尺寸、透明度、解码、像素预算等校验；等比例缩小的完整画幅按原有规则恢复尺寸。

新增合成测试覆盖 16:9、4:3、9:16 全画幅、等比缩放、返回尺寸信息、差一像素的裁切 / 填边拒绝，以及错误比例和超大输出拒绝。**这些是图像处理边界测试，不是三种比例的真实模型验收。**

验证中实际修复的联动问题：

- 删除用途后旧 EXACT 引用仍留在对话：保留用途管理集合并同步移除，补实际点击验证。

- 换项目残留旧任务列表：清空列表，自动插图再次筛选项目 ID。
- 归档失败被误记为已插入：失败不写成功账本，原任务重试归档成功后可继续入画布。

## 6. 与原方案的有意差异

1. **没有直接放宽图层比例校验。** 原方案也要求先查失败数据，当前缺少证据；本轮先做可诊断错误和边界测试。
2. **错误、恢复入口保留。** 自动读取取代正常状态下的刷新按钮；服务端冲突、权限变化、未知受理或超时仍有明确出口。
3. **素材入口采用方案允许的底部工具栏。** 右侧保留单一对话，素材通过按需窗口使用。
4. **没有增加拖拽任务记录到画布的另一套交互。** 已放入的结果隐藏插入按钮，未放入的结果保留恢复入口。
5. **画布顶栏仍显示文档保存状态。** 被收起的是重复的对话草稿成功提示；文档未保存和冲突状态继续可见。

## 7. 仍需核实与发布边界

- **真实分层故障**：需要那条失败任务的原图尺寸、模型输出尺寸和原始图层，才能判断是取整、裁切、填边还是其他问题。先读已有结果，不自动重复付费调用。
- **真实端到端验收**：本轮未重新验证真实账号、数据库、队列、存储和模型全链路，也未声称生图、PSD 或非方图分层的真实产出质量已验收。
- **发布**：本轮成果留在本地工作区；没有推送、CDS 配置、正式环境更新或 main 合并。远端不会因此自动变成这一版。

分层位置已实现：调用方明确选择右侧分组模式，旧共享函数默认行为保留；原图可见，分组可选择、撤销和重开，重复展开保持已有编辑。后续发布前核对目标分支和实际运行版本，并把真实服务验收记录与本轮交互测试分开保存。

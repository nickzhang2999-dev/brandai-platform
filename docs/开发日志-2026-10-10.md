## 后续定位 · 公网域名授权导致原生编辑器退出

用户反馈 f8aa44f 仍为空白、没有提示。线上记录补齐了实际顺序：canvas/toolbar 已同时存在并发送 ready；之后出现与本地正常运行并存的 FingerprintError；22 秒后两节点均不存在，但普通错误边界、两条原生崩溃标记均未出现。这不是此前的创建请求 403。

两个子智能体交叉核对，锁到原包 `originals/static/js/lib-tldraw.e6518aa1.js:16` 的许可组件：

1. HTTPS 非本地回环域名会执行生产授权校验；捕获资源里的显式许可只覆盖原模板域名，不覆盖当前评审域名。
2. 状态为 `unlicensed-production` 或 `expired` 时，先挂载编辑器，5 秒后将整个子树替换为 `data-testid="tl-license-expired"`。
3. 该冻结包的替代节点是 `display:none`；许可消息输出函数也为空实现。因此既没有用户可见提示，也不经过全局异常、`[canvas-crash]` 或 `.tl-error-boundary`。
4. 原调用 `lovart-canvas.358a3a91.js:24` 显式传入许可参数；只增加默认 `TLDRAW_LICENSE_KEY` 环境变量不能覆盖它。

**真实复现**：自签名 HTTPS 测试域仅解析到 127.0.0.1，运行原 SDK 自身的签名/域名校验，不伪造授权结果。画布和工具栏挂载后约 4992 ms 同时消失，留下隐藏许可节点；外层页头、Service Worker 仍在，其他崩溃标记均无。新父页提示的另一次测试约 4994 ms 触发并可见。线上同一隐藏节点的最终确认仍需新版结构诊断，不能把本地复现记为已经读取用户 DOM。

这也解释原本所有 HTTP/localhost 的浏览器长测为什么能通过：它们没有覆盖公网生产域名条件。此前将本地编辑通过用于推断线上编辑可用，验收覆盖不足。

官方资料核对于 2026-10-10：[tldraw 许可配置](https://tldraw.dev/sdk-features/license-key)、[许可说明](https://tldraw.dev/community/license)。官方明确说明域名授权、开发与生产环境区别、无有效许可时延后停止渲染。冻结包中“隐藏节点且不输出消息”的细节来自本仓库代码，不泛化为所有 SDK 版本。

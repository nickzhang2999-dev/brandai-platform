## 二、自动部署范围与延迟启动

### 现象

开发目标是在独立整合环境验证新前后端，但公司原 CDS 项目也启用了 Git push 自动部署。向整合分支推送代码时，公司原项目会创建或启动同名分支服务，并沿用原项目的部署配置。

临时关闭 push 自动部署、完成推送并恢复设置后，当日收尾复核再次发现该分支已经启动到 `f968f1a`。记录中的最近部署时间为 **2026-10-08 09:51:31 UTC**。

### 影响与归因

- 代码备份推送同时触发了不希望发生的环境部署。
- 独立环境的 CI 验收门禁没有覆盖公司原项目的另一条自动部署路径。
- 停止正在运行的分支，不会自动阻止后续 Git 事件再次启动它。
- 开发代理（小克）未在首次推送前核对完整自动部署范围，后续又过早恢复开关，属于操作控制缺口。
- 延迟触发的内部原因仍需结合 webhook、任务派发和部署队列记录确认，目前不能直接认定为 CDS 队列缺陷。

### 已处理与待处理

已通过 CDS API 停止仅该整合分支。服务端返回“所有服务已停止”，随后回读状态为 `idle`；公司 main 仍为 `running`，提交为 `e99919a`。push 自动部署开关恢复为原值 `true`。

后续需要明确每个分支的自动部署目标，确认平台是否支持分支排除或白名单，并核对关闭、恢复开关时对已接收事件和待执行任务的处理。不能仅凭 `git push` 命令结束，就判定可以恢复自动部署。

## 三、共享数据库与初始化影响

### 现象

公司原项目意外部署整合分支时，使用了共享 PostgreSQL、Redis。启动脚本会执行数据库迁移与 seed（初始化数据），因此即使 main 代码没有变化，共享数据仍可能受到开发分支启动的影响。

### 已确认的事实

- 早先的意外部署已在共享库执行新增 `EditorDocument` 表的迁移，记录时间为 **2026-10-08 06:38:04 UTC**。
- 当时查询该表为 0 条记录；这是当时的核查结果，不代表后续状态。
- 两次启动初始化分别创建了演示品牌。
- seed 同时执行了四档套餐的 upsert；缺少执行前的数值，无法断言套餐配置完全未变。
- 10 月 8 日收尾时，`f968f1a` 是否继续执行迁移或 seed 尚未核实；10 月 9 日[只读审计](cds-shared-audit-2026-10-09.md)已确认新增四张工作台状态表、一个演示品牌、三条关联合规词，并执行四档套餐 upsert。套餐字段缺少变更前快照，不能声明业务值完全未变。

### 已处理与待处理

已建立独立整合项目，使用独立数据库、Redis、持久卷、网络、会话密钥和队列前缀。后续测试应在该环境进行。

上述只读核查已于 10 月 9 日完成，后续处理应以该审计范围为依据。当前未擅自删除演示数据、回滚表或覆盖套餐配置。不能将“分支已经停止”或“main 提交未变”作为“共享数据没有变化”的证据。

## 四、配置导入与服务连接问题

### 现象

- 两次配置导入都获批准，但旧导入晚于新导入生效，产生了额外的 AI/Worker 基础服务配置。
- 配置中的部分自引用环境变量没有得到实际值。
- 过长的服务或容器名称导致内部 DNS 解析失败，出现 `ENOTFOUND`。
- 初始凭据仅有公司项目作用域，创建独立项目返回 `403 project_key_cannot_create`，需要完成独立项目授权。

### 影响与处理

这些问题增加了环境准备和排查时间，也容易造成“配置已批准，但实际运行状态不符合预期”。它们分别涉及导入顺序、配置值、网络命名和权限范围，不能合并认定为一个平台故障。

已完成独立项目授权；通过配置同步移除该项目中多余的服务配置，保留数据卷；补齐独立环境所需配置，并设置可解析的服务别名。独立环境的 Web、Worker、AI 健康检查及已有后端公网验收已经通过。

## 五、公网代理与来源校验不一致

### 现象与原因

公网部署后，品牌切换接口返回 403。应用看到的 Next 内部地址与浏览器实际访问的公网地址不同，原有 Origin 校验没有正确适配部署代理路径。

这是应用与部署环境的适配问题，现有证据不足以将其认定为 CDS 代理故障。

### 处理结果

已优先使用服务器配置的公开应用地址进行来源校验，同时继续拒绝陌生来源、伪造转发地址和错误协议或端口。公网品牌切换、保持，以及文档保存和重开检查已通过。

## 六、预览入口与访问验证未对齐

### 现象与原因

点击公司项目右侧分支的预览按钮时，进入了说明页或登录页，没有直接进入工作台。排查时服务仍在运行，主要涉及预览入口路径及评审访问验证尚未完成。

“服务运行中”“预览地址可访问”和“用户可以直接进入目标页面”是不同的验证项。

### 处理结果

原评审分支已配置访问入口。独立产品整合环境仍保留已验证的 `8474347` 版本，入口为登录页；新版 `/studio` 需要完整 UI 验收和独立部署通过后再切换。

访问凭据不写入本文，也不通过取消访问保护来解决入口问题。

## 八、后续处理顺序

1. **核实共享数据库影响**：只读检查最后一次意外部署是否执行迁移或初始化。
2. **收紧自动部署范围**：固定分支与目标项目的映射，核对延迟任务处理方式，解决后再推送。
3. **固定独立环境配置**：保留单一有效导入版本，核对服务、数据库、网络及实际运行提交。
4. **继续应用联调**：修复草稿响应及契约差异，完成离页保存和全新浏览器恢复验收。
5. **验收后更新独立 CDS**：部署精确通过检查的镜像，验证公网行为，再切换工作台预览入口。
